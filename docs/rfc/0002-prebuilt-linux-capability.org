#+title: RFC 0002: Immutable Released Gerbil Capability
#+author: gerbil-bazel maintainers
#+language: en
#+options: toc:2 num:t

* Status

- Decision: Accepted
- Implementation: released Linux capability and Homebrew Darwin bottle
- Scope: Gerbil-Bazel distribution boundary

* Context

Gerbil-Bazel owns toolchain discovery, registration, and Bazel rule
consumption.  A consumer's =build.ss= remains the semantic owner of its module
topology.  Compiling Gerbil itself inside ordinary consumer CI duplicates the
distribution layer, makes cache eviction unexpectedly expensive, and couples
library validation to upstream bootstrap time.

* Decision

Gerbil-Bazel is exclusively a release consumer.  A cache hit may reuse the
exact selected toolchain.  A cache miss MUST download an immutable Release
asset with a pinned SHA-256; it MUST NOT clone or compile Gerbil source.

The public =gerbil.prebuilt(...)= provider imports a relocatable Gerbil archive
by URL and digest.  The cross-platform =gerbil.auto(...)= provider selects one
provider before repository creation:

- Linux uses the immutable prebuilt capability;
- Darwin discovers the selected Homebrew installation, whose bottle is itself
  downloaded from the tap's Release page;
- unsupported platforms and architecture mismatches fail closed.

Provider selection observes both =module_ctx.os.name= and =module_ctx.os.arch=.
The module extension therefore remains =os_dependent=True= and
=arch_dependent=True=, with platform-specific evaluations retained in the
Bzlmod lockfile.

#+begin_src mermaid
flowchart LR
  CI["Consumer CI"] --> CACHE{"Exact toolchain cache"}
  CACHE -->|"hit"| TC["Registered GerbilToolchainInfo"]
  CACHE -->|"miss on Linux"| RELEASE["Pinned Release archive + SHA-256"]
  CACHE -->|"miss on Darwin"| BOTTLE["Pinned Homebrew Release bottle"]
  RELEASE --> VERIFY["Manifest, platform, version, ABI verification"]
  BOTTLE --> VERIFY
  VERIFY --> TC
  TC --> RULES["compile / test / dev rules"]
  RULES --> BUILDSS["build.ss semantic owner"]
#+end_src

Toolchain production is owned by the distribution release pipeline.  It may
build upstream Gerbil while producing a new immutable release, but those build
steps, checkpoints, promotion schemas, and runner policy are not part of this
consumer library.

* Public Bzlmod API

#+begin_src starlark
gerbil = use_extension("@gerbil_bazel//gerbil:extensions.bzl", "gerbil")
gerbil.auto(
    name = "local_gerbil",
    expected_version_prefixes = ["Gerbil v0.18.2"],
    linux_prebuilt_arch = "x86_64",
    linux_prebuilt_install_digest = "<64 hexadecimal characters>",
    linux_prebuilt_sha256 = "<64 hexadecimal characters>",
    linux_prebuilt_urls = [
        "https://github.com/tao3k/gerbil-bazel/releases/download/<release>/<archive>",
    ],
    project_root_marker = "//:gerbil.pkg",
)
use_repo(gerbil, "local_gerbil")
register_toolchains("@local_gerbil//:registered_toolchain")
#+end_src

Every prebuilt declaration carries two independent proofs:
=install_digest= identifies the installation capability and =sha256= identifies
the downloaded bytes.  Download, digest, manifest, platform, version, or ABI
failure stops repository creation; there is no host or source-build fallback.

* Project package ownership

=project_root_marker= identifies the consumer's canonical =gerbil.pkg=.  The
provider reads its =depend:= declarations, strips revision suffixes only for
installed-path lookup, projects ready packages into =lib/<package>=, and
records =ready= or =missing= in =toolchain.receipt.json=.

There is no second dependency-list override.  Dependency scope belongs to
=gerbil.pkg=; consumers must not repeat that graph in Bazel
configuration.  Dependency installation remains the explicit
=@<provider>//:install_dependencies= target, which delegates once to native
=gxpkg deps --install=.

* Archive contract

The prebuilt archive contains =gerbil-bazel-capability.json= and a relocatable
=prefix/= tree.  The manifest declares the schema, capability identity,
version, platform, native ABI fingerprint, Gerbil home, tool paths, dependency
roots, and environment.  All paths are relative and traversal-free.

The repository rule validates:

1. archive SHA-256 and installation digest shape;
2. manifest schema and safe paths;
3. host OS and architecture;
4. =gxi --version= against the manifest and accepted prefixes;
5. the native ABI fingerprint;
6. availability of =gxc=, =gxi=, =gxpkg=, and =gxtest=.

Nested Gerbil processes receive the selected capability's =PATH=,
=GERBIL_HOME=, =GERBIL_GSC=, Gambit runtime mappings, and normalized native
compiler environment.  The installed toolchain remains immutable.

* Gates

- Ordinary CI MUST NOT contain a Gerbil source bootstrap path.
- A cache miss MUST materialize from an immutable Release page.
- Missing or invalid assets MUST fail closed.
- Fresh download, registration, and smoke verification SHOULD complete within
  120 seconds.
- CPU, memory, compiler, assembler, linker, and Darwin SDK selection remain
  consumer-host capabilities and are not frozen into an archive.
